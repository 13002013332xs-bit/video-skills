# 批量合作邀请配置

适用于用户已确认的紫鸟联盟邀约流程。教学、读取商品、制作配置面板不自动授权发邀约或删除草稿中的达人；当前任务明确授权后执行，不逐条重新确认。邀请文本须使用用户当次确认内容，不能沿用页面旧草稿。

## 入口与字段

1. 核对完整账号名单及50/50计数，点“批量邀请”。
2. 选“创建新邀请”→“仅佣金”→“邀请”，进入创建页。此入口点击不代表已发送。
3. 名称为`自动批MMDD（语言）`，如`自动批1020（英语）`，最多30字符，名称同用UTF-16计数口径。
4. 日期统一读取**紫鸟后台显示的店铺日期**，用于命名、截止日期及当月重叠判断；不替换为电脑日期或自行选定的美国时区。无法可靠读取时待核对，不猜测。
5. 有效截止日期为店铺当天**加20个日历日**：10月20日→11月9日，10月19日→11月8日。不能用“当天第1天”算成加19日；处理跨月、跨年和闰年。
6. 店铺日期、语言、名称、截止、电子邮箱、电话均由代理处理，不让用户填写：语言跟随本次达人筛选条件，邮箱沿用紫鸟系统自带值，电话留空。面板只在可折叠的只读区域展示这些自动信息。缺少自动字段来源时代理在执行前读取，不用旧草稿值覆盖，也不阻塞用户先确认话术和商品配置。邀请文本最多500字符；按后台计数口径，当前已实测为JavaScript字符串长度（UTF-16），部分表情占2个单位。空白正文不能作为用户已确认内容。
7. 内容形式当前可选“带货视频”“带货直播”“暂无偏好”。

字段限制为现场快照，执行前核对当前控件。名称/正文显示实时计数，超长不截断后擅自发送。

## 商品与佣金

打开“选择商品”→“添加商品”，读取当前店铺的完整分页列表，包括完整商品名、商品ID、价格、成交、库存、状态与添加日期。不要把“还能添加N件”误认成商品目录总数；目录会变化，不能固化一次观察的数量、商品或价格。

配置面板参考`assets/invite-config-template.html`：提供搜索、多选、分页及按商品ID绑定的逐行配置。公开模板的数据为空，使用前将`invite-catalog-data`中的`products/shopDate/language/contactEmail/sourceDate/contextKey`替换为当次私有数据；不要发布填入真实数据的副本。每款商品数据结构为`{id,name,priceText,sold,stock,status,addedDate,samplePaused,unavailable,imageData}`。contextKey区分店铺，恢复状态不能跨店铺；恢复草稿仅恢复用户填写项，日期/语言/系统邮箱重取当前来源，电话始终留空。执行时重新读取日期与校验商品可选性。

搜索商品列表和已选商品列表均显示按商品ID对应的真实缩略图。imageData可放当次授权浏览器截图中裁出的私有缩略图；核对图片与行内ID，不能用同名商品、占位图或错图替代。图片来源缺失/加载失败时明确标记缺图，不能声称图片齐全；待补齐后重验。真实图片、私有链接及图片数据不进入公开模板、提交消息或保存的交互状态。

- 单次邀请最多100款。商品同名、截断或不同规格不能混用，以商品ID核对。
- 每款填标准佣金率；店铺广告佣金可独立开启/关闭，开启时填广告佣金率。当前两项输入提示均为1.00%–80.00%；面板校验该范围并保留至多两位小数。后台规则变化时更新约束，不自行设佣金。
- 后台商品选择框禁用时记录现状，不能伪造可选。若禁用仅因已在当前草稿选中，区分“已选”与“不可选”；其他禁用原因未核实时不猜。暂停样品也不能等同商品不可邀约。
- 广告佣金关闭不宣称广告订单佣金为0；具体沿用后台适用规则。

## 免费样品

“提供免费样品”开关独立选择。开启时有两种审批方式：

- **使用商品级别的样品设置**：沿用商品审批规则及限额；未设规则的商品需要手动审核。
- **批准此邀请中的所有人**：自动批准本邀请达人的**免费样品申请**，不是自动接受所有合作或消息。

不能替用户默认开启自动批准；面板初始可跟随当前已核对状态，提交时明确所选值。

## 重叠：按达人汇总后处理

先读取重叠表内旧邀请名称、对应完整账号和商品，遍历相关分页。同一达人可能有多个商品/旧邀约，不能把每行当不同达人。使用店铺日期判断所属月，并处理命名日期缺失、年份或记录歧义；不能可靠判定就标待核对。

| 旧邀请 | 对当前邀请的处理 |
|---|---|
| 名称为“自动批”且属于店铺当月，如当月10月的`自动批1019（英语）` | **从当前邀请名单移除该达人，保留旧邀请** |
| 不属于店铺当月，名称含“手动” | 移动至本次邀请 |
| 不属于店铺当月，名称不含“手动” | 移动至本次邀请 |
| 属于当月但非“自动批”，或日期/身份无法判断 | 待核对，不从旧规则推导移动授权 |

同一达人若任一冲突命中“当月自动批”，优先移除本次名单中的该达人，不先整体选择“移动至此邀请”。在“选择达人”列表用**该达人对应行右侧垃圾桶**移除；不是删旧邀约、删达人账号或全局拉黑。只有所有相关冲突均可移动时才执行移动；混合未知先核对。

移除后刷新名单、重叠状态及剩余人数。不能仍报告50人，不擅自补人或修改已定产品/日期来绕过冲突。公共模板中的冲突函数只是辅助分类，不会自动操作后台。

## 配置提交与真实发送

面板“确认本次邀约配置”把邀请文本、独立的紫鸟私信、产品ID/佣金、样品方式及自动字段处理规则回传对话（已读到的日期/语言可附带，只作当次快照），不自动发邀约或私信。正文分别保存为`message`和`ziniaoMessage`；配置包含私信流程时分别要求非空、分别计数和校验，不能把原邀请文本自动复制成私信。不得把填好字段、打开预览、点过入口或请求成功当作已发送。

实际发送按当次授权：提交前回读完整账号名单、实际人数、产品ID及佣金、样品审批、正文、店铺日期和冲突结果；提交后核对后台保存的邀请名称/状态和实际达人数量。未完成现场邀请提交和结果回读时，明确只验证了读取与本地面板，不声称完整自动化已跑通。

## 邀请成功后的紫鸟私信

这一步在紫鸟联盟后台完成，与原合作邀请的“邀请文本”及手机私信分别确认。用户教学截图中“发送邀请”模态框右侧正文显示`399/500`：已用399、上限500。面板独立提供“紫鸟私信”填写框、500上限及实时计数，初始留空，不采用页面自带模板或历史正文。面板暂按UTF-16计数；后台私信的表情、换行及用户名替换计数尚未实测，实际发送前核对当前控件的上限与计数，不能沿用原邀请正文的实测结论冒称私信计数已核验。若含用户批准的用户名变量，替换后逐人核对长度；超限不擅自删改话术。

在当次对象、内容与外发授权齐全时，按以下顺序执行：

1. 创建邀请页核对配置及重叠处理后的实际达人名单，点击底部“发送”一次。结果不明先查已保存邀请，避免重复提交。
2. 核验“合作邀请发送成功！”及对应邀请保存结果，再点“向达人发送消息”；只进入这一步不能宣称已发送私信。
3. 在“发送邀请”模态框准确选择本次实际剩余达人，核对完整用户名及选中计数；不能继续假设50人，也不能重选已因当月冲突移除的达人。
4. 开启“Send message with invitation”，填入用户当次确认的**紫鸟私信**，核对预览、字数及邀请卡归属。平台预填内容或“使用模板”不代表用户确认。
5. 收件人、已确认正文和卡片均正确后点击“分享”。重开会话/持久化消息记录，分别核验邀请卡与私信是否保存，并写入台账；只见按钮点击、短暂气泡或邀请成功页不能代替此核验。部分成功、未知、明确失败分别记账，核验之前不重发。

教学与面板配置本身不授权上述真实“发送”或“分享”；两份正文的内容确认也不等同外发指令。原邀请正文未确认或紫鸟私信未确认时，不用另一份正文顶替。消息开关开启不等于消息已发；0位达人选中不能分享。

手机私信及已读回复跟踪是后续独立步骤，按任务范围、身份核验与台账执行，不因合作邀请或后台私信完成而冒称已发手机私信、已读或已建立持续监控。
