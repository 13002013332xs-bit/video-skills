# 执行与证据

## 只在授权执行建联时读这一节

先读 `opencli-usage` 与 `opencli-browser`，通过当前帮助发现命令。检查站点适配器是否覆盖所需动作；没有私信能力时，使用浏览器桥。不要把“适配器身份读取失败”直接等同于“用户浏览器未登录”；读取已绑定标签页的可见登录状态，无法确认发送账号则停止发送准备。

已验证的连接入口：

```sh
opencli doctor
opencli browser creator-outreach bind
opencli browser creator-outreach state
```

`doctor` 要确认 daemon、extension、connectivity 均正常；绑定后核对网址和当前发送账号。复用用户已登录标签页，保持同一会话名。历史中 CUA 读取 Chrome 超时，不能凭进程存在推断网页可控；同一读取失败不要反复长时间重试。

## 一个达人

1. 将用户名与台账核对，保留原始用户名，规范化时仅去掉外层空格和前导 `@`；不删掉句点、下划线。对有歧义的名字核对主页身份。
2. 从当前主页实际读取消息入口和目标会话身份，不编造用户 ID 或复用另一个人的会话 URL。页面加载未完成与“没有私信入口”分开；加载一次后仍不明则记待核验或跳过。
3. 操作前取新 `state`/`find`，页面切换后重新取。只使用当下观察到的元素，不固化历史编号、选择器、按钮次序或 `--nth 0`。
4. 多行话术用当前工具的 `fill`，检查 `verified` 和实际文本；不能用逐字 `type` 的换行代替填入。填入成功只证明草稿正确。
5. 核对收件人和内容后，用现场确认的发送控件；不要把 `Enter` 当作已验证的发送方式。
6. 记为 `attempted`，重载列表核对当前消息并按台账规则更新。保存可读证据，定位到账号、收件人、内容指纹和时间。列表虚拟滚动时可定向打开目标会话核实，避免只凭顶部若干条下结论。

互动只有当次授权包含时执行。关注、点赞都先读状态，点后复检同一控件；不使用点赞数不变作为唯一失败依据。一次未确认就记录失败或不确定，不通过连点补数量。

## 收尾与恢复

每个达人结束立即落盘，不把多人操作结果仅留在工具内存里。长任务拆成短步骤；中断后先读台账并核实 `attempted` / `uncertain`，不能从脚本的“已发送”字样恢复。

批间下一次允许时间取实际上一批末条时间计算，记录时区；不要复用旧聊天助手算过的时刻。用户说到点再叫，就等其指令；不要由普通发送任务自行创建定时或后台任务。用户明确请求定时时，按当前自动化工具与授权范围处理，历史某版本的故障不泛化成永久产品结论。

公开或同步技能时只保留规则、字段与脱敏例子。凭据、Cookie、完整名单、真实私信正文、历史页面快照及带令牌链接不进入技能。
