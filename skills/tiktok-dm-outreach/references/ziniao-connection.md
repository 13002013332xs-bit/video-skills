# 紫鸟连接的精简步骤

适用于已选定店铺后接通控制窗口，以及用户关闭窗口后要求重新打开。只负责连接和页面就绪；不改变本轮筛选与发送授权。

## 准备与复用

- 先读取当前项目指定的操作记忆和规则，定位连接相关段落及最新纠正；不用每轮遍历全部历史、脚本和台账。同一会话中已完整读取、未变化的工具说明不重复加载；命令参数已验证时直接复用，不逐项重新查帮助。
- 复用本轮已确认的店铺ID和期望名称；首次使用、换店或身份不明确才查询店铺列表。共享商品目录不提供登录权限，不硬编码原作者账号、页面目标或机器路径。
- 按当前环境的紫鸟技能要求做必要的就绪检查；同任务环境未变化且检查仍有效时不重复运行。只有实际错误才进入对应诊断，不无条件重新登录、安装或升级工具。
- 已有有效可控窗口时直接复用。用户明确关闭窗口并要求重开时，使用已确认店铺身份打开，不先反复探测已经关闭的旧页面目标。

## 打开与一次页面核对

使用当前环境已验证的CLI参数；下面的值必须来自本轮确认和实际页面，不能直接照抄占位符：

```bash
ziniao-cli store open --id '<已确认店铺ID>' --expected-name '<已确认店铺名称>' --url '<已观察的查找达人地址>'
```

- 将URL、标题、页面可见状态和达人卡片是否可读合并为一次只读`page exec`；同时检查返回的`exceptionDetails`及本次实际`targetId`。不为普通页面核对额外截图或逐项回读。
- 打开返回的`launchUrl`只表示启动意图，不能证明页面就绪。实际仍为`about:blank`时，在用户设置筛选之前，用本次实际目标执行一次`page visit`修复导航，再合并回读确认。已在正确页面时不重复导航；加载中按实际条件等待，不以固定长等待代替核对。
- 确认所选店铺的正确查找达人页可读后，立即告知用户设置后台条件。只打开店铺和确认页面这项工作，不扩展为商品目录重读、历史名单审计或邀约准备。
- 保存本轮有效目标和连接状态。后续用户设好条件后保持同一窗口及有效目标，不再`store open`、导航、刷新或重置筛选。失联先识别原因；可能重开并丢失用户筛选时，不能承诺原样保留。

## 耗时说明

如需反馈速度，分别记录打开窗口、必要的空白修复与页面加载、读取核对的实测耗时。一次调用快不等于全流程耗时，个别样本也不是固定时限承诺。规则和已验证命令直接复用，异常处理按当前环境的紫鸟技能执行。
