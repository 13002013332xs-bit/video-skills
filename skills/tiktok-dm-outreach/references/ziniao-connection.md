# 紫鸟连接的精简步骤

适用于接通当次选择店铺的控制窗口。连接方法通用，店铺身份、实际页面和控制目标按店铺分别核对；不改变本轮筛选与发送授权。

## 用户确认的四点优化

1. 复用已验证的连接步骤，不每轮重新研究命令。
2. 必须读取的操作记忆和规则只定位相关部分，减少大段历史检索。
3. 已有所选店铺的可控窗口时，直接读取当前页面；正常就复用，异常才诊断。
4. 一次核对店铺、页面和卡片是否可读，核对完立即交给用户设置条件。

## 准备与复用

- 先读取当前项目指定的操作记忆和规则，定位连接相关段落及最新纠正；不用每轮遍历全部历史、脚本和台账。同一会话中已完整读取、未变化的工具说明不重复加载；命令参数已验证时直接复用，不逐项重新查帮助。
- 复用本轮所选店铺已确认的ID和期望名称；首次使用、换店或身份不明确才查询店铺列表并准确匹配。按店铺保存有效目标和实际URL，不跨店套用。共享商品目录不提供登录权限，不硬编码原作者账号、页面目标或机器路径。
- 按当前环境的紫鸟技能要求做必要的就绪检查；同任务环境未变化且检查仍有效时不重复运行。只有实际错误才进入对应诊断，不无条件重新登录、安装或升级工具。
- 已有所选店铺的有效可控窗口时直接读取当前页面，正常就复用；实际异常再按原因诊断。是否需要打开窗口取决于当次所选店铺的实际状态，不将一次关窗测试写成通用重开规则。
- 店铺商品目录、用户已设筛选和本轮配置分别隔离；切店核对新的店铺身份、页面和控制目标，不沿用上一店铺的商品、佣金、话术或筛选状态。

## 打开与一次页面核对

使用当前环境已验证的CLI参数；下面的值必须来自本轮确认和实际页面，不能直接照抄占位符：

```bash
ziniao-cli store open --id '<已确认店铺ID>' --expected-name '<已确认店铺名称>' --url '<已观察的查找达人地址>'
```

- 将URL、标题、页面可见状态和达人卡片是否可读合并为一次只读`page exec`；同时检查返回的`exceptionDetails`及本次实际`targetId`。不为普通页面核对额外截图或逐项回读。
- 打开返回的`launchUrl`只表示启动意图，不能证明页面就绪。实际仍为`about:blank`时，在用户设置筛选之前，用本次实际目标执行一次`page visit`修复导航，再合并回读确认。已在正确页面时不重复导航；加载中按实际条件等待，不以固定长等待代替核对。
- 确认所选店铺的正确查找达人页可读后，立即告知用户设置后台条件。只打开店铺和确认页面这项工作，不扩展为商品目录重读、历史名单审计或邀约准备。
- 保存本轮有效目标和连接状态。后续用户设好条件后保持同一窗口及有效目标，不再`store open`、导航、刷新或重置筛选。失联先识别原因；可能重开并丢失用户筛选时，不能承诺原样保留。

## 邀约成功后的新标签衔接

页面工具不能枚举新标签、默认exec仍读取旧目标的环境，采用已经验证的真实地址接入路径：成功页立即进入向达人发送消息；从当前授权紫鸟窗口的原生标签/地址栏读实际私信URL，核对当前店铺；将原受控target导航至这个已观察URL，再依据新鲜原生标签观察选中该受控标签，回读visible及实际发送邀请弹窗后继续填写和分享。不能猜计划ID、固化窗口ID/坐标或跨店复用目标。已有正常可控私信弹窗时直接继续，不重新执行入口。

在上述工具限制下，不再使用不带target的page exec循环寻找新标签；该写法已经失败，不能作为兜底。其他环境已有经现场验证的直接新target绑定仍可保留，不能因为当前环境的限制一并删除。

## 耗时说明

如需反馈速度，分别记录打开窗口、必要的空白修复与页面加载、读取核对的实测耗时。一次调用快不等于全流程耗时，个别样本也不是固定时限承诺。规则和已验证命令直接复用，异常处理按当前环境的紫鸟技能执行。
