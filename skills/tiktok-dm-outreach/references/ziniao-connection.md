# 紫鸟新接口固定执行入口

当前接口：**`zn-open-eco agent tool`**。这是紫鸟达人筛选、邀约及紫鸟私信的指定入口；不自动调用`ziniao-cli page/store`或旧轮包装脚本。旧接口仅保留历史证据，不在正常轮次读取或回退。新接口异常先告知用户，定向处理当前阶段；用户明确同意换接口前保持新入口。

## 只读当次需要的内容

正常开始直接复用当前已验证路径；只定位当前成功索引、本轮必要规则及状态，同轮未变内容不重复读取。成功路径只写适用条件、有效步骤和自检结果；错误命令、失败尝试及故障过程单独归档，不混入成功步骤，不作为启动必读或自动回退。仅实际异常时定向读取对应诊断记录；未验证的新方法单独标记，不列为已成功。

正常开始/恢复只读项目当前规则、唯一记忆的当前入口及[当前主流程](creator-workflow.md)，连接阶段才读本文件，再按阶段读取必要资源；同轮未变的内容复用。不遍历旧轮脚本、历史错误、全部台账或全部工具说明。维护才读取reliable-execution及相关失败证据，旧记录不能覆盖当前指令。

## 建立或复用连接

1. 先绑定用户选定店铺及当轮范围；不同店铺独立保存当前`browser_id`、`task_id`、活动标签和已核验的店铺身份。已有正常上下文直接复用。
2. 首次新任务按当前安装的官方workflow完成必要的一次能力/鉴权检查；换店或身份不明才精确查询店铺。真实命令参数查当前CLI/schema，同任务复用。不重新安装、重复doctor或遍历进程。
3. 已有受控页时，使用新browser的`tabs list/select`及页面读取，一次核对实际店铺、URL和卡片。无可用窗口才通过新CLI的`browser open --store-id`打开；导航必须在用户设条件前。已可读的上下文不为bootstrap重复navigate。
4. 用户在该窗口设条件后，不刷新、重新打开、重置或导航离开。当前轮次从私有状态文件恢复，不从旧面板补条件。

`browser_id/task_id`取本轮真实值，不能照搬别人的店铺、端口、计划ID或机器路径。共享商品目录不提供登录权限。

## 已走通的原生操作

实际工具schema由当前`agent manifest`取得，同版本同任务复用。固定传输入口为：

```python
from ziniao_agent import AgentClient, read_batches, ProgressGuard

client = AgentClient(
    browser_id=current_browser_id,
    task_id=current_task_id,
    evidence_dir=current_round_directory,
)
# 仅示意调用形状；JS和CSS必须来自当前已观察页面。
value = client.evaluate(observed_readonly_js)
client.browser('set_checked', {'ref': observed_checkbox_css, 'checked': True})
```

- `scripts/ziniao_agent.py`负责新接口调用、原样验证、有限等待和计时；当轮适配器只提供现场CSS和读回，不复制临时传输脚本。普通点击必须显式`expect_file_chooser=false, download=false`，不JS点击或改表单值。
- 工具给出`required_verification_call`时，下一动作前执行其**相同action和params**；即使前一步是只读evaluate也一样。共用脚本自动完成；验证失败则停在该动作，不重放业务点击。
- 先读明确总数，再用`read_batches`每段最多5项读取完整数据，校验每段项数；预览、`data_omitted`、截断及缺行都不能当完整结果。按工具要求使用variable_storage记录已采集集合。
- 滚动使用真实容器或当前已观察目标的`scroll(ref=...)`，读实际位移和卡片数后再决定继续；使用ProgressGuard阻止重复无进展循环。短暂无新增先确认加载/分页/末尾，不能据此断言平台没有更多达人。
- 硬条件先筛，缩略图仅用于影响分档的候选；本屏候选合并后统一勾选。截图前确认目标在视口、图片已加载；灰色占位不当无人。是否强制真人出镜是当轮变量，不覆盖PPS/成交分流表。
- 邀约用共用`ziniao_flow`调度及新接口原生适配器。商品按已确认ID定位；连续填完统一检查。冲突顺序仅按当前主流程第8节：集中排除后统一移动，关闭残留列表，有剩余就重开、确认50/页再循环。
- 邀约名称/批次按中国日期，截止及重叠按店铺日期。账号集合、实际人数、商品ID和冲突状态按当前页面核对，旧轮记录不是实时值。

## 成功页接紫鸟私信

完整流程仍是发送邀约成功后立即点“向达人发送消息”，不先“查看邀请”。新接口原生`tabs list/select`用于绑定真实新增标签；校验实际店铺和私信弹窗，替换已确认正文并分享一次。已就绪直接填写，不重新做连接诊断。

**验收边界：**新接口已现场完成筛选、商品添加及冲突处理；新接口整段发送/成功页私信尚未现场验收。上述发送顺序是业务要求及当前新接口适配方向，不冒称已经跑通，不为验收额外外发。下一次获得完整执行授权时，只通过新接口接好该阶段；真实不通立即告知，不暗中回退旧控制。

## 结果、学习与耗时

每个阶段保存当前状态、正常流程已有结果和计时；工具耗时与调用间空档分开，空档原因不明就明确不明，不能都称后台加载。脚本仅记录调用元数据，不记录凭据、正文、截图或达人名单；私有业务证据由当轮适配器按需另存，不进公开包。

每次新方法现场成功后，立即将适用阶段、工具版本、必要参数及结果证据写入项目指定的唯一操作记忆，并更新本文件或相应共用实现；正常入口只保留当前可执行的成功方法。旧方案、失败及诊断保留在历史证据，正常轮次不读取、不自动尝试。只有离线回归通过时标记离线，不提升为现场验收。
