# 紫鸟达人筛选与卡片核验

先由代理通过控制接口建立或复用可操作的紫鸟窗口，进入查找达人页并确认能操作，再由用户在这个窗口设置原生条件。设置后复用同一窗口和有效目标，不再开店铺、刷新或重设。对话确认筛选方式、PPS及本轮邀约配置。完整筛选面板保留作用户另行要求代理设置时的备用。

筛选方式、PPS和邀约配置均按当轮确认，明确文字可替代面板点击。同轮已确认不重复问，旧草稿不自动沿用。筛选本身不授权外发。

## 每轮先选快速筛选或内容复核

每轮在PPS面板增加必选的二选一项，初始不选，不默认沿用上一轮。未确认方式先记录其他配置，补齐方式后执行；用户明确说“快速/慢一点并看内容”等文字也算本轮选择，无需重复点按钮。

- **快速筛选（fast）**：不进入TikTok网页版做账号/视频复核，只选满足当次硬条件且可直接按卡片通过的两类：PPS≥4.7且视频缩略图有人出镜；PPS≥4.7且无人出镜、成交件数>500。需复核、身份/出镜看不清的候选本轮跳过并记为未复核，不判成内容不合格。明确告知可能错过低PPS但内容好的达人。
- **内容复核（content-review）**：保留已确认的卡片直接通过路径，对当次硬条件内低PPS、偶尔出镜、无人出镜且成交100–500（含500）及看不清等需要复核的候选，实际到电脑TikTok网页版匹配完整用户名、看主页与视频，按下文综合标准判断。浏览中遇到需复核候选就处理，不能先用直接通过者凑满目标而持续搁置这些候选。可直接通过的达人无需全员看视频；目标达到后停止扩展候选，不承诺全站穷尽或零漏选。网页无法查看保留待核验，不声称已复核，也不擅自切为快速模式。

两种模式都严格遵守本轮PPS硬范围和后台条件；慢模式不是放宽最低分。快速模式遇PPS低于4.7的整段范围可能没有直接通过者，此时如实说明，不自动提分、放宽或换模式。需要纳入更低分由用户修改本轮范围。内容复核继续使用画质、卡片均播≥200（适用场景）、讲解、无人出镜至少3次切镜头及既有高数据例外，不另造门槛。

面板以独立`screeningMode`及`profileReviewRequired`传递，不能塞进紫鸟原生`backendFilters`或把模式当作PPS值。保存草稿包含当前`roundKey`和模式；恢复仅限相同轮次。生成面板时把本轮唯一key注入根元素的`data-round-key`，同轮复用该key；新轮生成新key，不接受旧轮选择。未注入key的通用模板只在当前实例保存模式，不跨实例沿用。轻量进度分别记录选择的模式、卡片判断与实际视频复核，不把看过教学示例或缩略图写成当前候选视频复核。

## 已有准确名单：优先一次批量查找

用户已用页面截图示教：将要查看的多个达人名字一起输入页面上方的大查找框，再执行一次查找，可在同一结果列表查看多位达人卡片。已有准确账号名单时优先走这条路径，替代逐账号重复搜索；上方大查找框与单账号搜索控件按当前页面分别识别。

1. 将本批完整用户名一起输入查找框，保留句点、下划线和原始拼写。用户示例含逗号和换行；具体输入格式与控件按当前页面核对，不编造固定分隔协议、人数上限或已测速度。
2. 执行一次查找，在结果列表按完整用户名逐卡匹配名单，读取PPS实际分数、成交件数和平均播放量。批量结果可能包含相似账号或推荐项，不能以昵称、排序或结果数量认定全部命中；卡片名字截断先取得完整名字。
3. 核对已匹配名单与缺漏名单，列表有分页或懒加载时继续读取相关结果。仅对仍缺失或无法确认身份的账号单独补查，结果无法确认时保留待核验，不用相似名字补位。

这是用户确认的优先操作方法；截图教学不等于代理已完成现场批量查询或速度验收，也不授权勾选、邀请或发送。真实名单、截图和卡片数据留私有项目。

## 人工挑选的第一步：看视频缩略图中的人物

用户演示未设置筛选条件时的挑选顺序：先查看达人卡片下方的视频缩略图，判断画面有没有人物出镜。观察对象是视频封面区域，不以卡片头像代替视频出镜证据。

逐张记录有人、无人或看不清；缩略图看不清时保留待核验，不猜测。用户提供的本次正例为三个视频缩略图都可见人物。主页复核查看前6–7条缩略图的出镜情况；偶尔出镜按下述综合内容标准复核，不自行设置最低出镜张数、比例或必须露脸的门槛。未出镜时结合下述思路和其他证据判断，不一律淘汰；其他当次已设置的筛选条件继续独立按原样执行。

用户补充的未出镜反例：三张视频缩略图展示商品、包装或工具操作，没有人物主体出镜；其中即使可见局部手部，仍归为“未出镜”。头像有人也不改变视频缩略图的结论。由此按用户标准区分人物出镜与单纯商品展示/手部操作，不进一步推导必须露脸或全身出镜。

## 用户示教中的选人思路与已确认偏好

用户讲解的是选人时的思路，应区分已确认的处理偏好、举例和尚未明确的条件。主动用对比案例提问，弄清指标之间如何取舍及内容好坏；不能从个别例子推导所有未说明组合。以下“通过/合作”表示选人判断，不授权立即点击邀约或发私信。

先看PPS，再看出单量。PPS≥4.7（含4.7）是用户认为不错的数据：缩略图有人物出镜时直接考虑合作；无人出镜时，出单量100–500（含500）先看账号视频，超过500才直接考虑合作。用户已单独确认刚好500先看视频；这优先于早期400的示例。低于4.7不一律淘汰，仍可通过内容复核考虑合作。

指标位置已由用户截图确认：卡片中间“成交件数”就是用户说的“出单量”；右侧“平均播放量”就是讨论“播放约200”时查看的指标。不自行把成交件数换算成真实订单数，也不自行取主页前6–7条视频计算平均值来替代卡片指标。用户现已明确：低PPS或偶尔出镜的内容复核，卡片平均播放量要求≥200（含200）；覆盖早期仅以“约200”举例的记录。该门槛适用于这两个复核场景，不自行扩展到其他已明确的直接考虑合作分支。

需要看视频时，读取紫鸟卡片顶部达人完整账号，保留原始拼写、句点和下划线；截断时先取完整账号。直接在电脑浏览器打开TikTok网页版，输入完整用户名搜索，核对同一账号后查看主页和视频，按下文标准复核。筛选与内容复核不连接手机，不打开iPhone镜像或手机App，也不把手机连接作为开始筛选的前提；手机仅用于后续用户另行安排的手机私信流程。进入主页不等于通过；缺评分、数量、出镜或实际视频证据则保留待核验。

本节启发式思路与用户在当次筛选面板明确选择的硬条件分别处理；明确选择的PPS分数/范围等仍严格执行。只有用户明确确认某条为硬性准入或拒绝条件，才按硬条件保存；同步技能和项目规则时保留这种确认状态。

实际找人时，数值匹配之后仍按用户已示教的好达人判断路径筛选：哪些分支可直接考虑合作、哪些需看主页/视频，均依下文执行；不能只因数字合格就选，也不擅自扩大视频复核或豁免范围。邀约阶段处理重叠后按最终剩余名单执行，不回头补人。用户以20人举例，不将20固化为每批数量。

### 已了解的权衡与视频复核方法

- 在对比案例中，用户会直接通过“无人物出镜、PPS4.8、成交600件”的B；对“真人出镜、PPS4.6、成交200件”的A则先看主页，若基本都是真人出镜讲解产品、紫鸟卡片平均播放量约200，也会选择。保留为案例，不把卡片有出镜且4.6误写成无需内容复核，也不把出单200与平均播放200混淆。
- 进入主页后先看整体视频画质，按用户指定的好画质正例与差画质反例校准（真实账号及样本留私有项目，公开技能不收录身份）。再看前6–7条视频缩略图有没有人物出镜，然后打开其中一个视频看实际内容。不能把缩略图看见人等同于已确认真人讲解产品，也不自行将某个分辨率、照明或设备型号设成用户门槛。
- 内容复核通常偏好有准备、开门见山介绍产品或礼物用途的开场，如“看看这个产品”“这是很好的圣诞礼物”；不接受明显没准备、反复磕绊含糊且讲不清产品的表现。判断清晰、连贯与准备程度，不用固定台词白名单，也不因一个语气词或“父亲礼物”题材本身淘汰。下述高数据例外可放宽开场准备要求。
- 无人物出镜也可以合作：用户看重视频内容丰富；现已明确普通内容复核要求单条视频切换镜头至少3次（含3次）。按镜头之间的实际切换计数，起始镜头不算一次切换；连续3段镜头只有2次切换，恰好3次满足这一数量条件，少于3次不满足。次数达标仍结合内容丰富度等已确认条件判断，不能仅凭次数自动通过；无法确认次数则保留待核验。无人物出镜且全程单镜头讲完通常不合作。用户已确认PPS≥4.8（含4.8）且出单量≥500（含500）时，即使不切换镜头、开头讲解没准备也可通过。该条件豁免这两项内容不足，不据此推导差画质也被接受。刚好500仍按上述最新边界先看账号，之后可用这个例外判断内容，不以例外跳过已要求的复核。
- 用户认可的无人出镜正例：产品和局部手部为主体，视频在使用场景、不同角度或景别的产品细节、拆装/功能演示、携带及不同款式对比之间切换。观察这些变化如何丰富产品展示，用于理解“画面丰富、多次切镜头”；这些是示例镜头，不要求每条视频集齐；切换次数按上述至少3次（含3次）核验。只抽查一条时，结论限于该样本画面；音频、全账号表现及其他候选分别核验，不能因题材相同自动通过。
- 用户已提供好/差画质账号参照，并确认PPS更低仍有合作机会；低PPS与偶尔出镜都回到同一综合复核：画质好、紫鸟卡片平均播放量≥200（含200）、讲解得好、视频内容丰富。不能仅凭PPS低或出镜少淘汰，也不能只凭播放量达标通过；不自行设置全局最低PPS或最低出镜比例。缺少卡片播放量等证据保留待核验，不能用主页单条播放或自行抽样均值补齐。普通无人出镜视频继续按至少切换3次（含3次）核验；原高数据内容豁免保持适用范围。用户当次明确选择的PPS硬条件继续严格执行，内容好不用于绕过该条件。
- ≥200是含边界，200满足、199不满足；不能把该要求错误应用为后台严格大于200。好差画质参照、200边界和偶尔出镜的复核方式均已回答，不再重复询问；其他未明确组合按现有证据判断或标待核验。

### 真人正例中归纳的观察维度（待用户确认）

用户已认可多位真人出镜账号为好达人。对各账号的单条产品视频抽样，并结合实际音轨的本地转写，可归纳以下候选观察维度；这是代理的分析，尚未成为用户确认的硬条件：

- 有效出镜：人物在介绍、指示、拿取或操作产品；不把露脸张数或时长当作产品讲解能力本身。
- 具体讲解：能说出用途、方法、适用人群或所解决的问题；用来观察信息是否具体，不要求每条作品集齐固定结构，也不核定广告中的性能主张为事实。
- 信息丰富度：画面是否新增部件、功能、细节或使用效果等产品信息；真人动作与展示变化也可作为线索。此候选维度不改动已确认的无人出镜至少3次切换及高数据例外。
- 场景适配：居家、车库等普通环境也可有清楚的主体及合适的产品展示；不自行要求摄影棚、空白背景或固定技术参数，仍按实际画面与用户正反例比较。

不从用户认可账号推导所有作品都好，也不推导最低出镜比例、统一开场台词或真人视频全局切镜头次数。主页单条播放与置顶爆款不能证明紫鸟卡片平均播放、PPS或成交件数合格；缺少同口径数据保持待核验。原始身份、链接、截图、媒体和转写仅留私有项目。用户确认或纠正这些候选维度后，再更新其确认状态。

## 粉丝与视频播放量

- 两项均使用单轨双滑块，下限与上限分别可拖，也可手输精确数字；键盘、数字与滑块同步。滑块不能交叉，手输反向范围提交时拦截。
- 粉丝刻度0、1万、10万、100万、1000万+；视频刻度0、100、1000、1万、10万+。五刻度等距，中间值分段插值，不声称逆向了后台全部算法。最高滑块最右端代表不限上限，以`max:null`保存；输入确切数字则保持有限上限。
- 视频后台只确认支持严格大于下限，保留独立“按带货视频数筛选”勾选。完整值保存到`exactValues`，后台的`backendFilters["video-views"]`仅传`min`与`shoppable`。有限上限传`cardFilters["video-views"]`，含上边界，再读取相同统计口径的指标核验。
- 勾选带货视频时不得用全部视频平均播放量代替；指标缺失或口径不明，标记待核验，不计入合格。未设上限不额外限高。旧状态缺少`max`时恢复为不限。
- 例如下限321、上限6789且勾选带货：后台应用`>321`及带货口径；随后核验对应平均播放量`<=6789`，不能只应用下限便称全部满足。

## PPS实际分数

PPS不是紫鸟原生筛选项，是用户额外要求的达人卡片核验条件。先应用后台条件，再核对每个候选的PPS。

- 卡片`4.9 / 5.0`中，左边4.9为实际分数，右边5.0为满分；只按左边判定，不取右边、不算比例、不四舍五入后凑入所选分数。
- 用户明确选4.5、4.6、4.7、4.8时，`4.9 / 5.0`排除。用户列出离散分数时只匹配这些分数，不自行补中间值；用户选最低/最高范围时两端均含边界，单端未选为该端不限。
- 当前面板分数选项按用户指定：5.0、4.8、4.7、4.6、4.5、4.4、4.3、4.2、4.1、4.0、3.9；未加入4.9。这个选项表不影响读取卡片上的4.9并排除它。
- 分数不可见、为“-”或无法准确读取时，标记待核验，不计入合格；不当0、不假定满分。没有设置PPS条件时不额外限制PPS。
- `backendFilters`不包含PPS；`cardFilters.pps`保留用户选择与含边界语义。可用`scripts/creator_pps.py`对已读取的PPS文本确定性判定；它不抓页面，也不执行外发。

## 面板复用与执行

`assets/creator-filters.html`是可在对话中显示的完整点选面板，已内嵌上述公开选项快照；引用时遵守当前客户端的可视化能力。`window.openai.widgetState`恢复草稿，交互后保存完整私有选择，提交时用`sendFollowUpMessage`传完整原始值和可读标签。按钮使用`type=button`及click事件，兼容未授权表单提交的沙箱；不得为修表单降低沙箱限制。
