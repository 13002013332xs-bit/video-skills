# TikTok 网页版界面地图与踩过的坑

以下元素名在 2026-09 的 TikTok 网页版（Chrome，中英文界面）实测确认过。
界面语言会影响文案（「消息/Message」「发送/Send」），写正则时两种都要兼容。

## 达人主页（`tiktok.com/@<用户名>`）

| 用途 | 无障碍树里的样子 |
|---|---|
| 进私信 | `link 消息, Value: tiktok.com/messages?lang=xx&u=<用户ID>` |
| 点关注 | `按钮 关注 <显示名>` → 点完变成 `弹出式按钮 已关注 <显示名>` |
| 视频列表 | `link Value: tiktok.com/@<用户名>/video/<视频ID>` |
| 关注数/粉丝数 | 形如 `标题 1013 已关注 导出关注 3303 粉丝 导出粉丝 31.1K 赞` |

要点：

- 「已关注」这个字样在**左侧导航**里也有（`link 已关注, Value: tiktok.com/following`），
  判断关注状态时要看**主页头部那一段**，不要被导航栏的同名链接骗了。
- 有点达人的主页没有「消息」入口（对方关了私信），这时跳过私信，从名单替补里补一个。

## 视频页（`tiktok.com/@<用户名>/video/<视频ID>`）

| 用途 | 无障碍树里的样子 |
|---|---|
| 点赞 | `切换按钮 点赞视频 <数量> 个赞, Value: 0/1`（1 = 已赞） |
| 评论 | `按钮 阅读或添加评论 ...` |
| 收藏 | `按钮 添加到收藏...` |

点赞就在视频页，**不要在主页缩略图上找**——缩略图那一层没有点赞按钮。
页面里可能同时有多个视频，取第一个匹配即可。

## 私信页（`tiktok.com/messages`）

| 用途 | 无障碍树里的样子 |
|---|---|
| 输入框 | `文本输入区 (settable) 发送消息..., Value:` |
| 发送按钮 | `按钮 发送`（英文界面是 `按钮 Send`） |
| 表情 | `弹出式按钮 点击添加表情` |
| 字数 | 形如 `文本 523/6000` |
| 会话列表 | 每条是「名字 / 预览文字 / 时间」三行 |
| 已读信号 | `文本 消息请求已被接受。你们可以开始聊天了。` |

要点：

- **会话列表是虚拟滚动的**，只渲染最近约 30 条。找老会话要么往下滚动，
  要么用列表里的搜索，别指望一次性读到全部。
- 发送按钮的文案是「发送」，用 `\b` 之类的词边界去匹配中文会失效，
  直接匹配 `按钮 (发送|Send)` 更稳。
- 发成功后**输入框会清空**，这是最可靠的完成信号之一。

## 踩过的坑（都真实发生过）

1. **工具调用有 5 分钟上限**。一次塞 5 个达人进去会被截断，日志丢失但消息已发出，
   结果对不上账。**每批拆成 3–4 个达人调用一次**。
2. **浏览器窗口焦点会被别的窗口抢走**（同时开着其他 Chrome 窗口时尤其明显），
   无障碍树会返回别的窗口的内容，所有元素编号立刻失效。
   开工前确认窗口标题是 TikTok 页面；读到的状态不对时，请用户把 TikTok 窗口调到最前，
   并停止在 Chrome 里的其他操作。
3. **网址要"全选 + 粘贴"**，逐字输入会丢 `?`、`&` 这类字符，
   结果变成一次 Google 搜索。
4. **导航后要等**。TikTok 页面加载慢，导航后立刻读往往只拿到工具栏，看不到页面内容；
   等 6 秒以上，或读不到关键元素时再重试一次。
5. **不要只信"已发送"**。曾经出现过文案已填进输入框、但发送按钮没点中的情况，
   必须在发送后确认输入框已清空，并回列表核对预览。
6. **不要给对话挂定时任务**。定时任务触发时，内容会以一条缺少字段的记录写进对话历史，
   在部分模型接入方式下会让该对话之后的所有请求被接口整条拒收，
   表现为"这个对话再也回不了消息"。
7. **乐观 UI 会骗人**。点发送后，即便消息被服务端丢弃，会话里也会先出现一个气泡、
    输入框也会清空；过一会儿气泡消失，重新打开会话就什么都没有了。
    所以"气泡出现过"和"输入框空了"都不能作为发送成功的证据，
    **唯一可靠的判据是重新加载私信列表后能看到这条会话的预览**。
8. **静默限流**。当天冷启动私信累计到 30 条上下时，可能出现"发了没反应"：
    不报错、无提示，消息直接不落地。此时继续发只会白费，应当停止，隔一段时间再试；
    恢复后先发 1 条并核对列表。
