# 短视频选片与剪映交付

把当次脚本、画面结构和素材分类对齐，交付能继续细剪的草稿及全部预览。用中文沟通，先给能看的结果，再给简短说明。

## 开工入口

1. 先读接收者当前项目已有的规则与操作记录；未建立时按本技能和当前请求推进，不依赖原作者个人文件。同一适用范围内，较晚的用户纠正覆盖旧记录；数字、列位、路径、登录状态仍须现场核对。
2. 先确认当前工作根、可用脚本及实际输入/输出位置，不直接照抄其他电脑的旧 `work/` 命令。工作文件放当前项目 `work/`，交付物放当前 `outputs/`。分享版脚本存在历史流程限制，运行前按当前输入和参数验证。
3. 从当前请求和上下文提取：配音/脚本、逐拍顺序、素材区块、数量、重复率、交付形式。只问确实缺失且会阻塞的输入；已经明确的要求直接执行。
4. 只检查本次步骤所需依赖。内置看图或已存在的分析缓存可用时，不因缺某个云端 key 停掉整条流程。外部权限按当前工具反馈处理，不把历史沙箱限制当永久结论。

## 核心顺序

**结构 → 配音拍点 → 表中位置/功能 → 内容与入点 → 草稿/预览 → 独立验收。**

- 用户给的镜头数、顺序、合并/拆分方式原样执行。参考片每次切镜头计一镜，但用户当次指定结构优先。不把某个脚本的映射、禁用场景或秒数升级成全局模板。
- 本地词级转写可用 `vu-transcribe`；换配音必须重排拍点，不能沿用旧秒数。末拍终点取实际解码音频总长，向上取整到视频帧，包含完整尾音；不只看容器标记时长。
- **功能主判据是飞书单元格的小节；位置主判据是当批表头/列。** 按原始 cell 顺序保留 text 小节和 attachment 的归属。区块代号先查表，不解释成日期；旧 inventory、文件名、文件夹不能覆盖表中记录。
- **映射按产品和批次核对**：多功能笔 1010 的 B/C 开头、D–G 功能、H 结尾不能套到磁吸灯或全部历史批次。H 在某些旧批次是展示库；读原表头并结合本次需要判断。遇到同名素材保留区块/坐标/附件身份，不能用文件名覆盖索引。
- 小节按功能精确匹配（“笔”不等于“触控笔”），再匹配颜色和动作；文件名与小节冲突时暂不选，核实画面。表内查不到才用文件夹/命名兜底，并标明来源和把握度。
- 候选顺序：未用过的新批次 → 未用过的旧批次 → 在本次上限内复用。素材少也不能放宽功能定义；“拿刻字笔量水平”不等于“展示刻字”。按内容查重并检查画面相似性；同一条内零重复、开头不同。跨条目标零重复，用户未另设上限时沿用已确认的 ≤20%，报告实际分母和数值。
- 看完整动作过程，入点须包含动作及结果。高光工具只定位已匹配素材中的窗口，不能用高光分取代功能/类别。复用已验证分析缓存；短片也不能机械从 0.4 秒截取而漏掉动作。
- 每段实际可用视频时长须覆盖所需时长及速度。人工指定路径同样检查：不存在/不够长就报错，不能静默换片或截短。默认不靠慢放、定格、重复镜头、删配音补时长；结构变化须有当次授权。

## 默认生产与验收

默认按已确认流程：**原始素材复制进草稿、保留原始分辨率与可调整范围；1080×1920 竖屏画布；另出 540×960 轻量预览。** 画布尺寸不等于把源素材转成1080。原片不足以支持4K时如实说明；已有代理用于预览须验证与原片时间映射。

读 [references/current-workflow.md](references/current-workflow.md) 核对当前工具与旧流程限制。不要默认跑旧 `scripts/build_v2.py`，它会先转1080。草稿不能只引用剪过的成片段落，否则用户无法向前后拉素材。每条草稿使用独立资产/缓存目录。

交付前逐条检查：

| 必查 | 通过条件 |
|---|---|
| 结构及语义 | 每拍对应当次结构；类别、小节、颜色、动作/结果符合 |
| 源素材 | 路径有效；入点/速度/源视频长度足够；草稿逐段对应本次计划 |
| 时间轴 | 连续无空洞；画面覆盖配音；轨道终点差 ≥ −0.05s，末拍覆盖尾音 |
| 重复 | 条内0重复；跨条实测在本次上限内；开头不同且不只换文件名 |
| 草稿 | 资产自包含、素材有余量；索引登记核实；未改用户正在编辑的锁定草稿 |
| 交付 | 每条都有实际可播放预览；文件/草稿名和逐拍清单一一对应 |

校验用原表/独立对照，不复制选片函数自证正确。硬错误未解决就标明未完成，不能靠评分或“两轮后警告通过”放行。优先延长有真实余量的既有素材补足尾音；不够就停该条并说明缺口，不用 `-shortest` 截掉配音。

预览以本地绝对路径内嵌，附草稿名和逐拍素材清单；批量必须全部给到。新验证成功的操作路径写入接收者已有的项目操作记录，写明适用条件、命令、自检数值和失败写法。

## 旧工具和参考的适用边界

保留现有 scripts/references。执行优先级：当次用户要求 → 接收者项目中适用的最新纠正 → 本入口及 current-workflow → 旧参考。

| 资料 | 何时读、限制 |
|---|---|
| `reference-analysis-5aspect.md` / `transcription.md` | 拆参考片、词级时间戳；不能据此改用户结构 |
| `selection-rules.md` / `pick_clips.py` / `pick_fresh.py` | 仅作旧命名素材库兜底；关键词不能覆盖飞书小节，旧30%不是默认 |
| `jianying-draft.md` | 草稿结构、自包含、索引；旧默认转码/自动重名不能覆盖本次草稿流程 |
| `highlight-picking.md` | 已选素材的入点定位；单帧或高光分不证明语义正确 |
| `ffmpeg-correctness.md` / `mixing-rules.md` | 编码/音频机械规则；慢放、合拍、加镜头要满足当次授权 |
| `material-gaps.md` / `batch-consistency.md` | 素材缺口与系列风格；不得擅自拆拍、换表达、删用户片尾 |
| `self-review.md` / `pitfalls.md` | 定位问题与缓存经验；严重错误不得警告放行，权限按当前环境判断 |
| `voice-cloning.md` / `script-generation.md` | 仅在用户要求配音/脚本创作时使用；试听确认要求按当次执行 |

用户只说“检查飞书”时只查表、不自动下载；指定素材或当前剪辑任务确需且已授权时才下载。不因旧记录自动查表、写表、发消息或建定时/轮询任务。清理按当次授权和项目操作记录的适用范围执行；先确认代理覆盖/可恢复来源，不把历史某批清理授权扩大到所有文件。
