# 当前生产顺序与旧流程边界

此分享版保存原作者近期确认的生产方法；不依赖其个人电脑、私有素材表或项目脚本。接收者自己的当前规则、来源与授权优先。

## 入口按当前环境核对

| 工作 | 要确认的实际入口 |
|---|---|
| 读取飞书素材 | 接收者自己的已授权连接/CLI、真实产品表、当批表头、小节和附件身份 |
| 参考片和配音 | 当前参考文件、完整原配音、可用的词级转写工具 |
| 生成草稿 | 当前可验证的剪映生成器和草稿目录；原片通道需真实可用 |
| 预览和成片 | 当前渲染器实际参数、输出位置、画布、帧率和编码方式 |
| 配音生成 | 仅用户要求时使用其可用工具和授权；不附带账号或令牌 |

## 先准确选片，再少量下载

1. 一次提取当次镜头结构和完整原配音，按配音排拍点。新素材不够先找旧批次，不放宽功能定义。只要用户指定功能镜头作开头，就按该结构选片，清单保留原表实际来源。
2. 按当前表头、格内小节和源身份建立候选，复用已有代理及有效分析；不要每条视频重新扫全库。代理同名也可能对应不同附件，身份、时长、动作不一致时重新核对相关原片。
3. 看片同时核对动作开始、过程、结果及景别。复合动作全部可见，单帧、高光分、旧文件名不能证明语义通过。
4. 飞书可作为素材主库，但不为候选池批量下载全库原片。只补选中且本地缺少的文件，单项超时、成功逐项保存，只重试失败项；齐料的版本先推进。
5. 统计原片、草稿副本和渲染缓存的峰值空间，按单条视频分批推进。仅回收本轮新增且确认无引用的临时文件；旧草稿、历史交付和源素材不自动删除。

## 草稿与渲染

- 草稿复制完整原片，保留原分辨率及前后可调余量；代理只用于工作和预览，先核对时间映射。草稿资产自包含，不只引用裁好的成片段。
- 每条独立资产/缓存目录；缓存绑定源身份、入点、帧数、画布、帧率、速度和编码配置。改一拍只重做相关片段与衔接，更新必要的整批去重核验。
- 明确要成片时，可在工具支持并验证后一次解码产生成片与轻预览；只要草稿时不额外渲染高清。Mac可用硬件解码时先实测，失败回软件，保持既定编码质量。
- 用真实视频流可用长度检查源区间，目标时长×速度不能超出源余量。不得靠生成器静默clamp、慢放、定格、重复或删配音补时长。
- 配音以实际解码总长安排末帧，不取可能较短的容器标记；向上取整到视频帧，完整覆盖尾音。
- 草稿有锁或用户正在编辑时不覆盖；新草稿核对索引条目、真实ID、路径、封面和时长。若应用文件不是普通JSON，保留原文件，不盲跑旧JSON工具。

## 独立验收与交付

逐拍表保留视频/拍号/目标起止/台词/期望功能/源路径/表区块与坐标/附件身份/小节/款式/源入点/速度/可用长度/指纹/复用情况。

对照用户当次原句独立检查结构、动作和颜色；从实际草稿读时间轴，核对连续性、素材余量和完整配音；新输出检查实际帧数与音轨并完整解码。源身份与区间未变的有效结果可复用，技术检查不冒充动作核验或亲耳听审。

重复率分开报告条内、本批跨条和用户要求的历史窗口，说明分母；源哈希结合画面判断，不把素材重复率称作平台算法评分。文件验收与剪映界面验收分别说明，常规交付不等待已失败的界面入口。

合格结果就绪后提供实际预览、草稿名、逐拍表和验收数值。耗时区分选片、下载、渲染、验收及等待，纯渲染耗时不当作总交付速度。

## 现有旧工具限制

`scripts/build_v2.py`含历史转1080流程，`pick_clips.py`含固定镜头，`pick_fresh.py`依赖关键词，`render_preview.py`也需核对实际路径与行为。旧参考中30%重复、自动拆拍/改表达、慢放和严重问题警告放行不构成当前授权。原作者私有项目的批量下载/快速渲染脚本未随此包提供；不能声称这些旧程序已自动具备上述全部优化，迁移实现时需用真实输入验证。
