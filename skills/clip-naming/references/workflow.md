# 接片、分类与可选飞书归档

## 使用接收者自己的素材与授权

分享版保留原作者“本地接片→全段看片→命名分类→按需要上传”的方法。它不包含原作者素材、账户登录、飞书表标识或本机上传实现；历史“已获授权”不授予接收者额外权限。

先从本次请求与已有项目设置取得素材入口、输出位置和交付范围。用户只要求命名时，完成本地命名分类和清单；用户明确要求上传时，使用其有权限的目标表与当前工具。既有授权沿用，只补缺项，不强制每批全量重批。

## 本地处理

可沿用“素材根目录/产品/待命名上传、已命名待上传、已上传”的阶段结构，按实际拍摄日期分批；先核对接收者已存在的路径，不迁移历史库，不把示例路径说成已建立。没有自动监控程序时，用户告知传完后处理，不读取仍在传输的文件。

1. 确定产品，核对素材传完、文件身份、数量与拍摄日期。日期无法确认时补问，不自动用操作日代替拍摄日。
2. 按整体与产品专用规则全段看片、命名、分类；原片保留，命名版复制入对应路径，同名不覆盖。
3. 清单保留原名、新名、源身份、产品、大类、细类、小节和待确认项。仅具体歧义待确认，其他有把握条目自行推进。
4. 本地交付到用户指定目录；未要求上传时，到此即可完成，不强制配置飞书或云端视觉凭据。

## 已要求上传飞书时

1. 定位接收者有权限的产品原表，核对当批表头、格内小节、版本与空白区域。原作者方式为按拍摄日期新增分类区块；接收者明确要求其他方式时采用当次要求。
2. 核对接收者当前可用的文件附件上传接口和工具，先验证正确落位，再批量推进。此分享版没有提供原作者私有项目的上传脚本，不声称装技能即可自动登录或上传。
3. 上传真实原视频附件，保持已有内容和附件顺序；同格写入串行合并。只写文字/链接不算附件上传完成。
4. 回读核对附件名、数量、字节数、分类与失败项；只重试失败项。验收后才标已上传，原片继续保留在同批次存档；失败或待确认素材保留，不自动删除。

生成命名清单不等于用户逐字确认，也不等于已登记优先选片台账。确需登记时核对接收者现有入口，不另建未经约定的平行台账。
