# 素材命名与产品选择

名字用于剪辑检索：写清主要功能、动作和结果，再补能区分相似素材的款式、物品特征、背景、运镜或景别。规则按产品分别维护。

本分享版包含原作者已校准的个人命名风格，可直接沿用；参考中的“用户确认”指原作者的历史确认。接收者当次要求和自己的较新纠正优先。接收者自己的素材路径、账号、目标表及授权独立配置，不继承原作者的资源或上传授权。

## 开始命名时先确定产品

1. 读取接收者当前项目已有的 `AGENTS.md`、项目规则和操作记录；若未建立这些文件，直接使用本技能与当前请求，不因缺少原作者文件阻塞。只补确实缺失的产品、素材位置或交付信息。同范围当前用户的较新纠正优先。
2. 读取 [产品清单](references/products.json)。每次新一轮仅说“开始命名了”“帮我命名”且本轮未明确产品时，先展示清单中的全部产品及学习状态，追加“新增产品”，让用户选择。上次处理磁吸灯不等于本轮默认磁吸灯。
3. 有 `request_user_input_async` 时用它给出产品单选；否则直接发可用文字/编号回答的选项。此选择决定规则，收到选择后再开始依赖产品的命名、分类和归档；可先检查素材位置、数量与传输状态。普通命名任务不创建额外网页或面板。
4. 用户本轮已点名产品，直接采用；同一批继续工作沿用已选产品。混合产品先逐条识别、分别套规则，无法确认归属的条目单独问。
5. 先读 [整体命名规则](references/naming-grammar.md)，再只加载选中产品的 `rules` 文件与 [分类入口](references/taxonomy.md)。产品信息帮助理解，不替代客观看全段画面；演戏中的道具动作照实命名。

产品清单是唯一的选项列表来源。当前产品为磁吸灯、多功能笔、肌理画、多功能锤；清单新增产品后，下一轮选择自动包含它，不在多个文件里另写固定菜单。

## 命名与处理

- 覆盖全段看动作开始、过程、结果和背景；复用绑定源身份的有效分析缓存。只看封面、单帧或旧文件名不足以判断。
- 由整体规则及所选产品参考形成候选，再结合该产品的真实大类、细类、小节归类。模型给的简短名只是候选，须核对最新用户纠正。
- 主动拿具体片段确认真实歧义，不等用户追问；已经确认的词汇与授权沿用。用户传入前已筛好新片，收到的全部命名，不自行淘汰。
- 使用 [接片、分类与飞书归档](references/workflow.md)。本地命名分类与上传分别按接收者的实际请求执行；已明确授权的批次沿用授权，不重复问。单纯开始命名不自动向原作者或其他飞书表上传。
- 原片保留，分类命名版不覆盖同名文件。交付清单保留原文件身份、原名、新名、产品、分类、实际目标位置与待确认项。
- 用户说已经自行改好时，只吸收纠正并更新规则；按其要求决定是否还需修改本地文件或飞书，避免重复改动。

## 新增产品与继续学习

用户选择“新增产品”时，只补齐新产品名称和能定位的素材表/实片来源；先查现有信息，再补问缺项。建立该产品专用参考并加入 `products.json`，初始标为“待学习”。有原表时先读分类；无原表时从本地实片建立候选分类，再按真实分歧逐条校准。用户明确确认、原库观察和助手候选分别标注；已有共性规则可沿用，功能词和细类独立学习。

新产品完成了哪些样例校准就记录哪些，学习状态随证据更新；“肌理画已读原表”不等于已完成个人习惯校准。后续纠正写回对应产品文件；项目已有规则和操作记录时同步更新相应入口，保持来源一致，不为相同范围另建互相冲突的总记忆。不额外要求用户重新确认“是否保存规则”。

## 工具边界

优先复用现有全段分析、宿主看图及已验证工具。模型、凭据、依赖和输出路径按本次环境核对；不打印凭据，不为普通命名自动安装模型。

现有 `scripts/caption_clip.py` 可在核对接收者自己的配置后辅助抽帧描述；其输出仍须按本技能校正。`process_inbox.sh`、`name_and_file.py` 与桌面旧 command 保留历史用途，其中有默认磁吸灯、旧“短视频素材”目录和旧分类逻辑，尚未接入本产品清单。不要把这些旧批量入口当作当前多产品命名入口直接运行；本次更新的是 Codex 对话中的选择和执行规则，不宣称改好了旧桌面程序。
